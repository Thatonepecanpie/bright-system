# Source file template

Copy this into `references/sources/YYYY-MM-DD-short-name.md`. Leave out any section that doesn't apply. A tool
entry needs "What it is / when to reach for it" more than per-piece notes.

```markdown
# <Short name>: <author or site>

- **Link:** <the URL Fernando shared> (resolves to <final URL, if different>)
- **Author:** <name and handle>
- **Type:** inspiration | tool | resource
- **Added:** YYYY-MM-DD
- **Tags:** <kebab-case tags: product type, mood, colour, type style, technique>
- **What I could see:** <what the fetch actually returned, e.g. "one 640x548 preview frame, no caption">

## What it is
<Two or three sentences: what was shared and why it's worth keeping.>

## The pieces
<One short paragraph or bullet per design or screen: layout, colour, type, imagery, the one idea. Precise
enough to design from without the image. Mark guesses as uncertain.>

## Moves worth borrowing
<Named, reusable techniques, each with one line on where it would fit in Fernando's work.>

## Watch out for
<Where the reference stops being useful: hero-only, needs costly imagery, readability risks, etc.>

## For a tool: what it is and when to reach for it
<What it does, cost and access, and whether it can be used from a Claude session (connector, API, CLI) or
only by Fernando in its own app.>
```
